# ER Diagram

## ER-ALL
```mermaid
erDiagram
  FE_ASSET_ITEM {
    string filename
    string url
    int mtime
  }
  FE_UPLOAD_RESPONSE {
    string filename
    string savedPath
    int size
    string mimetype
  }
  FE_USER {
    int id
    string name
  }
  BE_ASSET_ITEM {
    string filename
    string url
    int mtime
  }
  BE_UPLOAD_RESULT {
    string filename
    string url
    int mtime
    string savedPath
    int size
    string mimetype
  }
  BE_USER {
    int id
    string name
  }
  DB_ASSET_FILE {
    string filename PK
    string saved_path
    string mimetype
    int size
    int mtime
  }
  DB_USER {
    int id PK
    string name
  }

  FE_ASSET_ITEM ||--|| BE_ASSET_ITEM : "DTO maps"
  FE_UPLOAD_RESPONSE ||--|| BE_UPLOAD_RESULT : "subset"
  FE_USER ||--|| BE_USER : "DTO maps"
  BE_ASSET_ITEM ||--|| DB_ASSET_FILE : "derived_from"
  BE_UPLOAD_RESULT ||--|| DB_ASSET_FILE : "writes"
  BE_USER ||--|| DB_USER : "reads"
```

### Assumptions
- DB_* entities are conceptual because the current implementation uses filesystem storage and in-memory users.
- FE_UPLOAD_RESPONSE is a subset of BE_UPLOAD_RESULT; fields like url and mtime are omitted on the FE type.
- Mappings are based on matching field names between FE/BE and not on a shared DTO source yet.

```mermaid
  }

    string id
    string status
    string title
  }
  USER {
    int id
    string name
  }

  ASSET_LIST_RESPONSE ||--o{ ASSET_ITEM : items
  APP_STATE ||--o{ ASSET_ITEM : assets
  APP_STATE ||--o{ UPLOAD_TOAST : toasts
  APP_STATE ||--o| ASSET_ITEM : selected
```

### Assumptions
- APP_STATE is inferred from React useState hooks in frontend/src/App.tsx.
- selectedFilename references ASSET_ITEM.filename when not null.

## ER-BE
```mermaid
erDiagram
  ASSET_ITEM {
    string filename
    string url
    int mtime
  }
  ASSET_LIST_RESPONSE {
    ASSET_ITEM[] items
  }
  UPLOAD_FILE {
    string originalname
    Buffer buffer
    string mimetype
    int size
  }
  UPLOAD_RESULT {
    string filename
    string url
    int mtime
    string savedPath
    int size
    string mimetype
  }
  USER {
    int id
    string name
  }
  EXPORT_ARCHIVE_RESULT {
    string filename
    Archiver archive
  }

  ASSET_LIST_RESPONSE ||--o{ ASSET_ITEM : items
  UPLOAD_FILE ||--|| UPLOAD_RESULT : saved_as
```

### Assumptions
- USER is currently returned from an in-memory list in DatabaseService.
- EXPORT_ARCHIVE_RESULT.archive represents a streaming archive object at runtime.

## ER-DB
```mermaid
erDiagram
  ASSET_FILE {
    string filename PK
    string saved_path
    string mimetype
    int size
    int mtime
  }
  USER {
    int id PK
    string name
  }
```

### Assumptions
- No relational database is implemented yet; ASSET_FILE models filesystem persistence.
- USER table is speculative to reflect the User DTO shape used by the API.
